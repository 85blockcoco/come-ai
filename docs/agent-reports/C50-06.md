## Verdict

**Méthode publique observée mais incompatible avec un connecteur GET : la liste des offres Workday exige un POST authentifié de rien, mais POST quand même.** Le site carrières Workday (`myworkdayjobs.com`) appelle un JSON non documenté officiellement, `POST /wday/cxs/{tenant}/{siteId}/jobs` avec corps `{appliedFacets, limit, offset, searchText}` ; un GET sur ce point d'accès renvoie **HTTP 400**. Les API Workday officiellement documentées (développeur) exigent toutes des identifiants par tenant (OAuth 2.0 / ISU) — aucune API d'offres anonyme n'est documentée. **Statut pour C50-07 : bloqué dans le contrat de transport actuel (GET seul, `get_json`)** ; seule une surface GET limitée existe (configuration `approot`, détail d'une offre dont l'identifiant est déjà connu).

Étude de la documentation officielle : `developer.workday.com/llms.txt` (GET public) — « Public documentation and API specifications are available without authentication », mais l'index ne documente que des API d'intégration authentifiées (REST/SOAP par tenant, OAuth 2.0 client credentials, ISU). ## Conditions d'accès pour un éventuel C50-07 (rien n'est appliqué)

1. **Contrat de transport actuel bloquant** : les connecteurs du dépôt (`career/connectors/lever.py`, `ashby.py`) utilisent un transport injectable `get_json(endpoint, timeout_seconds)` en GET uniquement. Le listing Workday exige un POST JSON : **aucun connecteur GET-only ne peut lister les offres Workday**. Étendre le transport à POST serait un changement de contrat partagé — décision d'intégrateur, hors périmètre de cette carte.
2. **Aucune API officielle anonyme** : la voie « documentée » (REST/SOAP Workday) exige des identifiants tenant (OAuth/ISU) — hors règles de gratuité et hors périmètre sans autorisation explicite.
3. Si un jour le POST était accepté : hôtes allowlist tenant par tenant dérivés d'observations verbatim uniquement (`db.wd3`, `ms.wd5`, ...), pagination `limit`/`offset` plafonnée, erreurs 400/500 typées selon le schéma ci-dessus, admission avant le plafond 150, migration additive du `CHECK provider IN ('greenhouse')` proposée non appliquée.
4. **Zéro scraping des espaces candidats, zéro authentification, zéro contournement anti-bot** : si le board exigeait des en-têtes de navigateur, le contourner est interdit.

- Le contrat CXS est **non documenté officiellement** (corroboration tierce : jobspipe.dev — « no documented API » pour la surface carrières publique) et varie entre versions de tenant ; le bundle analysé est versionné `2026.40.17` et peut changer sans préavis.
